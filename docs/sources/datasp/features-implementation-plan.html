01

Why we don't blend into every other submission

A router agent calling an LLM to write SQL over a spreadsheet is now a weekend-project pattern — dozens of public repos do exactly this. The problem statement is common ground. These six choices are where the gap actually opens.

Numbers come from code, not the LLM

The Analysis Agent computes every figure with pandas/DuckDB before the Narrative Agent ever sees it. The LLM narrates numbers; it never invents them. This is the single biggest lever on Explainability and Model Performance.

A Validator Agent that can say "no"

Every narrative is checked against the source computation before it reaches the user. Mismatches get caught, not shipped. Most teams demo the happy path only — we demo the refusal too.

Power BI as the boardroom layer

Almost every comparable public project ships a Streamlit chat window and calls it a dashboard. We pair a lightweight chat/agent UI for interaction with an actual Power BI report for the exec-facing view — it looks, and is, more enterprise-credible in a 3-minute demo.

Hybrid LLM routing

Cloud API as primary, local model as automatic fallback on failure or rate-limit. Most teams have one API key and one point of failure; a dropped connection mid-demo is a top-5 datathon failure mode we've simply removed.

A golden test set, shown live

~18 fixed business questions run against the system before judging, with a pass count we can put on a slide. "It works" is an opinion; "17 of 18 test questions pass, here's the one that doesn't and why" is evidence.

Every answer ends in an action

Not "revenue dropped 12% in Region West" — "revenue dropped 12% in Region West, driven by X; recommended action: Y; owner: Z; confidence: medium because sample size is small." Judges evaluating explainability and innovation are explicitly looking for this.

02

What we build, in what order

Must-Have is the floor a working, defensible, judged submission cannot fall below. Should-Have is where the score actually moves. Could-Have only gets touched once the first two columns are done and rehearsed. Won't and Can't are decided on purpose — read them before anyone "quickly adds" something at hour 19.

Must Have 11
  • End-to-end demo, 5+ questionsOne clean run per business domain: sales, finance, ops, customer service.
  • Real orchestrator routingIntent classification picks the specialist agent — no single mega-prompt pretending to be "multi-agent."
  • Live query executionData Agent generates and runs real pandas/SQL against the actual dataset, not canned answers.
  • Deterministic numeric layerAll figures come from executed code. The LLM only writes English around them.
  • Plain-English narrative agentA non-technical exec should read the answer in under 10 seconds.
  • At least one chart per queryAuto-generated, rendered inline, matched to the data shape.
  • Power BI dashboard, 4–6 KPIsBuilt against the real competition dataset, not a mock.
  • Visible agent traceWhich agent ran, what query it used — shown, not hidden.
  • Clean, reproducible reporequirements.txt, README with run steps, zero hardcoded secrets.
  • All 7 required deliverables presentSource code, AI/model pipeline, preprocessing pipeline, dashboard, docs, PPT, prediction/output file.
  • Rehearsed 3–5 min demo pathRun at least twice before judging, offline-safe wherever possible.
Should Have 10
  • Validator/Explainability AgentCross-checks narrative against computed numbers before the user sees it.
  • Confidence score on every answerHigh / Medium / Low, with the one-line reason.
  • Recommended-action layerWhat to do, who owns it, why — attached to every insight.
  • Hybrid LLM routingCloud API primary, local model fallback on failure or rate-limit.
  • Golden test set (~18 questions)Pass/fail tracked, ready to screenshot for judges.
  • GuardrailsMax agent steps, retry limit, explicit "not enough data to answer confidently" refusal.
  • Shape-aware chart selectionTrend → line, comparison → bar, composition → donut, distribution → histogram.
  • Messy-data moment in the demoShow one missing-value / mixed-type case handled live, not just the clean path.
  • One-page model/system cardDocuments known limitations honestly — judges ask for this directly.
  • Power BI slicer or drill-throughAt least one interactive element, not a static screenshot.
Could Have 6
  • Proactive anomaly agentFlags unusual spikes without being asked.
  • Multi-turn memoryFollow-up questions referencing the prior answer.
  • Voice inputPure demo flair — last thing built, first thing cut.
  • Exportable executive briefOne-paragraph PDF/text summary, auto-generated.
  • Second domain specialist agentE.g. customer-service ticket sentiment, beyond sales/finance/ops.
  • Live Power BI publish-to-web embedInside the chat UI, instead of pinned/static tiles.
Won't Have 7
  • Fine-tuning a custom LLMZero visible payoff in 24 hours, real risk of eating the clock.
  • Generic multi-dataset connectorBuild for the actual competition dataset, not a universal BI platform.
  • Login / auth / multi-tenant accessNot in the rubric. Not worth an hour.
  • AutoML / hyperparameter searchThe "model" here is the agent + data pipeline, not a leaderboard score.
  • Production security hardeningA clean .env and no exposed keys is enough for a demo-grade system.
  • Auto-generated Jupyter notebooksSome repos do this — it doesn't move any judging category here.
  • Mobile app / responsive PWAThe room sees a laptop screen. Build for that screen.
Can't Have 5
  • Guaranteed internet-free Power BI ServiceCloud Power BI needs internet. Power BI Desktop + a local .pbix file is the safe path.
  • Genuine enterprise / PII dataIt's a competition dataset. Don't overclaim privacy capability the demo can't prove.
  • Rigorous accuracy benchmark vs. ground truthNo time to build one. The golden test set + deterministic architecture is the honest substitute.
  • Zero-hallucination guaranteeNo system can promise this. The honest claim is "caught before the user sees it," not "never happens."
  • Fully autonomous high-stakes actionsKeep the human-approval checkpoint. Say why, out loud, when asked.

05

Stack, at a glance

Full reasoning and alternatives are in 07-tech-stack-and-tooling.md.

Agent orchestration

CrewAI (primary)

Role-based, fastest to stand up for a 3-person team in 24 hours. LangGraph only if the validator loop needs more explicit state control.

LLM — cloud

Whichever key is ready first

OpenAI / Anthropic / Gemini / Groq — pick one as primary based on available keys and rate limits on the day.

LLM — local fallback

Ollama or NVIDIA NIM

Small instruction model (e.g. llama3.1:8b / qwen2.5) kept warm as the offline/rate-limit fallback.

Data engine

pandas + DuckDB

In-process SQL over dataframes — no server to stand up, fast enough for the dataset sizes this event uses.

Chat / agent UI

Streamlit

Fastest path to a working, demo-able interface for non-technical users.

Dashboard

Power BI Desktop

Exec-facing KPI layer, refreshed from agent output — see section 04.

Charts (in-app)

Plotly

Inline charts inside the chat/agent responses, separate from the Power BI report.

Version control

GitHub, public or reviewer-access repo

Required by the event rules — confirm access before the countdown ends.
